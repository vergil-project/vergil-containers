# Release 2.1.49 (2026-11-23)

## CI

- **deprecate the report-only pin-exposure job (#1001)**
  Remove the pin-exposure job from ops.yml and its test; upstream-refresh is the path that fixes pin lag, and a lag it cannot fix fails that job (epic vergil-project/.github#1494, spec 5.5). A new test_ops_jobs.py asserts the job is gone. report_exposure.py stays, runnable by hand, and the version-management page now says so. Ref #988
- **pass the App secrets to the shared docs workflows (#1008)**

## Chores

- **refresh upstream inputs (#1011)**

## Documentation

- **drop the public-repo qualifier from the ad-hoc epic comment (#1005)**
  Every repository is now public and every repo's ad-hoc epic is homed in the org's .github, so the qualifier implied a private-repo case that no longer exists. Comment only. Ref #1003.
- **point the lifecycle comment at the manifest for the pr families (#1006)**
  The comment named the pr families as python and go, already stale since rust moved to pr. It now names docker/versions/manifest.yml as the list. Ref #997

## Features

- **remove license-checker from the ts-node images (#1002)**
  * feat(ts-node): remove license-checker from the ts-node images

  No Vergil gate runs license-checker any more: the TypeScript AUDIT check gates licenses with vergil-tooling's vrg-npm-license-gate, which reads the committed package-lock.json. Drop its global install, its build-time run check, its smoke-test checks and its mentions in the ts-node docs. prettier stays as the image's only TypeScript tool. Ref #964

  * fixup! feat(ts-node): remove license-checker from the ts-node images

- **label every image with the release and commit that built it (#1007)**
  * feat(publish): label every image with the release and commit that built it

  Each image built by cd-docker-publish.yml now carries org.opencontainers.image.version and org.opencontainers.image.revision, so a published digest names the vergil-containers release that built it. A prod run labels its images with the VERSION release and refuses to build unless that release's tag names the pinned commit; a dev run labels them with the next release and a -dev suffix. Refs #996.

  * docs(publish): say why a prod run's release tag already exists for the nightly rebuild too

- **report the container jobs to the operations queue (#1009)**
  Adds reporting jobs for nightly-rebuild-dev, nightly-rebuild-prod, image-publish (skipping release pushes), package-cleanup and package-cache-warm, each calling the ops-report action at v2.1 (epic vergil-project/.github#1494, Task 8). test_ops_reporting.py pins them and takes over the pin-exposure assertion from test_ops_jobs.py.
