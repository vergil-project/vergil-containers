# Release 2.1.45 (2026-11-17)

## Bug fixes

- **retry a transient upstream fetch failure in the lifecycle check (#948)**
  A network error, a timeout or an HTTP 5xx in fetch_url is retried up to three attempts in all, with a warning and a 5s then 15s back-off; a failure that lasts through every attempt still raises SourceError naming the URL. A 4xx or an undecodable body is never retried. Ref #946.

## Features

- **pin per-architecture digests in source for the remaining auto-managed prebuilt tools (#950)**
  Apply the TOOL_DIGESTS mechanism to hadolint, opentofu, nfpm, scorecard, trivy, uv and yq. Each fragment now pins its tool's SHA-256 per architecture beside its version and the build checks the download against it; the daily refresh writes the digests with the version. The resolver reads release-wide sha256sum lists and yq's multi-hash checksums as well as per-asset files. hadolint and scorecard move to fragments of their own so each digest-pinning fragment pins one tool, as the refresh path fence expects. Ref #945
- **add ts-node 26 (#949)**
  * feat(versions): add ts-node 26

  Node.js 26 became LTS on 2026-10-28, so it joins the ts-node window. The manifest, toolchain pin and generated files are rendered by the lifecycle check's own add path (lifecycle/apply.render_change); the image README and the policy page's dated status are updated by hand.

  * fix(ts-node): install libatomic1 so the Node 26 binary can start

  The nodejs.org Node 26.13.1 tarballs (x64 and arm64) load libatomic.so.1 at startup. ubuntu:24.04 does not ship it, so `node --version` in the install step failed with exit 127 and both ts-node:26 builds failed on PR #949. Node 24 and 22 are unaffected; the package is small and harmless there.
