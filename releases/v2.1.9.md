
# Release 2.1.9 (2026-07-15)

## Bug fixes

- **grant actions:read so CD starts with cd-release@v2.1 (#406)**
cd-release.yml@v2.1 now requires actions: read so its CI-evidence harvest can download the release PR's artifacts. A reusable workflow cannot request more permission than its caller grants, so calling it without actions: read fails CD at startup with startup_failure even on develop where the release job is skipped (the graph is validated at load). Grant actions: read in the top-level permissions block to fix the startup failure.

- **grant actions:read on the release job so CD starts (#409)**
#404 added actions:read to cd.yml's top-level permissions, which fixed the sibling repos whose release job inherits top-level permissions. This repo's release job carries its own job-level permissions block, which fully replaces the top-level block for that job and omitted actions:read. GitHub validates the reusable-workflow graph at startup, so cd-release.yml@v2.1 was still called with insufficient permission and CD failed at load with startup_failure on every push to develop — even though the release job is skipped there.

Add actions:read to the release job's permissions block, completing #404's grant at the level where the override takes effect.

## Features

- **add nfpm to base dev image for .deb/.rpm packaging (#407)**
Add a pinned, checksum-verified nfpm binary to the base image via a new common/nfpm.dockerfile fragment, wired in after the OpenTofu include so dev-base/prod-base and every language image that extends them carry it. nfpm builds .deb and .rpm from one declarative config with no rpmbuild/dpkg host tooling — package publishing is a cross-cutting need across the component family (the MQ family ships precompiled .rpm/.deb).

Pinned to current stable 2.47.0 (verified against the real release assets). nfpm's assets use x86_64/arm64 naming, so amd64 is arch-translated. Unlike OpenTofu's SHA256SUMS, nfpm's checksums.txt lists a .sbom.json entry beside each tarball, so the checksum line is selected by exact filename field (awk) rather than a substring grep that would match both and break sha256sum -c.
