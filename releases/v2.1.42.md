
# Release 2.1.42 (2026-11-15)

## Bug fixes

- **queue image publishes instead of cancelling the one in flight (#898)**
* fix(publish): queue image publishes instead of cancelling the one in flight

A later CD or nightly run in a prefix's docker-publish group cancelled the publish in flight, and nothing retried it. The group now queues (cancel-in-progress: false). A newer run that replaces a pending one publishes the whole matrix at the same or a later commit, and the versions job pins the commit every job checks out, so a branch that moves mid-run cannot mix trees in one publish. Refs #879, #820.

* docs(publish): state what a replaced no-cache nightly loses

- **force IPv4 and retry the apt.llvm.org apt steps in the C++ images (#905)**
The arm64 cpp-clang and cpp-gcc builds failed fetching from apt.llvm.org: apt connected to its IPv6 address, which the runners cannot route, and DNS resolution of apt.llvm.org failed. The inherited 80-vergil-fast-fail config already applies to these steps, but its 3 retries have no delay (kept for the mirror+file deadlock), so they land within a second and repeat the same IPv6 attempt.

A new shared fragment, common/llvm-apt, included by cpp-analysis, installs /usr/local/libexec/vergil/llvm-apt-get. Every apt-get step after the LLVM source is configured runs through it: IPv4 forced and 5 apt retries on that command line only, and the whole command rerun up to 3 attempts 15 s and 30 s apart. The last failure exits with apt-get's status, so the build still fails loudly.


## Build

- **run hadolint in validate-custom so local validation matches CI (#896)**
vrg-validate did not run hadolint, though PR CI's quality / hadolint job does, so a Dockerfile change could pass locally and fail CI. validate-custom now generates the Dockerfiles with docker/generate.sh and lints docker/*/Dockerfile with the repo's .hadolint.yaml, as the CI job does. Generation failure skips the lint so a stale Dockerfile is never linted as current. Ref #761


## CI

- **fail the nightly when the pin-exposure report itself fails (#902)**
* ci(ops): fail the nightly when the pin-exposure report itself fails

Drop continue-on-error from the pin-exposure job and run its step under bash with pipefail, so a crash of report_exposure.py is no longer hidden by the job setting or by tee's exit status. Findings stay informational: the script still reports them and exits 0. docker/versions/test_ops_pin_exposure.py pins the structure and runs the step with uv stubbed. Ref #819.

* docs(ops): correct the lifecycle job's contrast with pin-exposure

pin-exposure no longer has continue-on-error, so the language-lifecycle comment now contrasts how each job treats an upstream lookup failure. Ref #819.

## Features

- **add yq to the base image (#903)**
* feat(base): add yq to the base image

Install mikefarah's Go yq, the yq the GitHub-hosted runners carry, in a new common fragment the base template includes, so dev-base, prod-base and every image built on them can run the suites that need it under vrg-validate. The binary is verified against the release's SHA-256 checksum, its column located through checksums_hashes_order. The pin is auto-managed: the daily upstream refresh resolves its latest release. The base invariant checks assert yq is mikefarah's and reads YAML. Ref vergil-project/vergil-containers#884

* docs(architecture): list the yq fragment among base's shared fragments

Ref vergil-project/vergil-containers#884
