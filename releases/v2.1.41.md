
# Release 2.1.41 (2026-11-14)

## Bug fixes

- **decode gzip and deflate response bodies in the upstream fetchers (#888)**
apt.llvm.org now answers a request with no Accept-Encoding with a gzip body, which urllib returns undecoded, so the cpp-clang lifecycle check failed on a non-UTF-8 index. Both fetchers (lifecycle/sources.py and pins/resolve_toolchains.py) now send Accept-Encoding: gzip, deflate and decode the body through a shared stdlib-only helper, content_coding.decode. An unsupported coding or a body that does not decompress raises SourceError (ResolutionError in the pins), never undecoded bytes. Ref #883.


## CI

- **move the nightly ops cron to the 01:xx UTC hour (#881)**
GitHub schedule events fire 7 to 9 hours late, landing the nightly run in the US Eastern working morning. Moving the cron five hours earlier keeps the lagged run overnight. The minute (per-repo stagger) is unchanged; the version-management doc's stated run time is updated to match. Ref #880

- **add cargo-nextest to the rust images (#890)**
Install cargo-nextest from nextest's prebuilt release tarball, verified against the release's per-asset .sha256, in a new common fragment the rust template includes, so every rust image (dev and prod, each toolchain series) can write JUnit test reports on stable Rust. The pin is auto-managed: the upstream refresh resolves its latest release through get.nexte.st, since nextest-rs/nextest also publishes other crates' releases. The build checks that cargo nextest runs and writes a JUnit report. Ref vergil-project/vergil-containers#885
