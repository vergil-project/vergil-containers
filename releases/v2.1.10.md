
# Release 2.1.10 (2026-07-16)

## Documentation

- **document image repoint rollback procedure (#427)**
Repoint a rolling tag at an in-window datestamp alias for instant Axis-B rollback with no rebuild: list in-window {version}-YYYYMMDD aliases, imagetools-create the rolling tag onto the good alias's digest, and open a fix-forward tracking issue. Links the pin re-evaluation lifecycle (spec 4.3) and the retention-window reaper. Mechanic demonstrated end-to-end against a throwaway local registry.


## Features

- **add pin data model, extractor, and CI justification gate (#423)**
pins.yml carries a justification per exact pin; check_pins.py fails CI on any undocumented pin or stale entry. Seeds every current exact pin (Task 3 audits them). The go-install regex resolves the tool from the last path segment before the optional /vN suffix so golangci-lint/govulncheck/go-licenses/gocyclo/goimports surface correctly, and load_pins reads docker/pins/pins.yml with root=docker/ so the CLI gate and tests share one scan root.

- **publish immutable datestamp image aliases alongside rolling tags (#424)**
Each build now also publishes {prefix}-{lang}:{version}-YYYYMMDD (and {prefix}-base:latest-YYYYMMDD) at the same digest, enabling repoint rollback.

- **generate the pin catalog from Dockerfiles + pins.yml (#425)**
CATALOG.md is generated (version facts from images, justifications from pins.yml) and CI-verified for staleness via generate_catalog.py --check, so it cannot drift like CLAUDE.md did.

- **reap datestamp image aliases on a sliding window (prod 30d / dev 7d) (#426)**
Adds a reap-aliases job to package-cleanup.yml that deletes {prefix}-{lang}:{version}-YYYYMMDD (and {prefix}-base:latest-YYYYMMDD) aliases once they age past the retention window (prod 30 days, dev 7 days) via dataaxiom/ghcr-cleanup-action older-than. delete-tags matches only datestamp aliases (dash + 8-digit stamp, use-regex); exclude-tags protects rolling/version, cache-*, and *-candidate tags. delete-untagged is left off, so untagged pruning stays the cleanup job's remit. Preserves the existing DRY-RUN default and the PACKAGE_CLEANUP_DRY_RUN / workflow_dispatch arming mechanism verbatim.

- **audit pins; free loud-failure tools, justify survivors (#428)**
* feat(pins): audit pins; free loud-failure tools, justify survivors

Freed the package-manager tools that float cleanly by dropping the version: markdownlint-cli (npm), yamllint/ansible-lint/uv/mkdocs-material/mike/pyyaml (pip + uv install script), golangci-lint/go-licenses/gocyclo/goimports (go install @latest), cargo-deny/cargo-llvm-cov (cargo install). Their pins.yml entries are deleted.

Kept the binary release-tarball tools as documented mechanism pins: shellcheck, shfmt, actionlint, git-cliff, hadolint, opentofu, nfpm. Their download URLs (and per-version checksum files) require an explicit version in the path, so they cannot float without adding an unauthenticated GitHub latest-version lookup to every image build. inducing_release stays null (not Tenet-6 break-avoidance); flagged for human decision (#418).

go-test-coverage keeps its existing inducing_release justification. Security scanners (trivy, scorecard, govulncheck) left untouched as seed entries; their freeing is gated on WS3 rollback (#422).

Build-verified dev-base and dev-go with nerdctl: freed tools resolved to current releases (markdownlint 0.48.0 to 0.49.1, ansible-lint 26.4.0 to 26.6.0, uv 0.11.14 to 0.11.29) while mechanism pins held. dev-rust deferred to CI.

* ci(hadolint): ignore pin-demanding rules for deliberately-floated installs

Freeing pip/npm/go pins (#418) makes DL3013/DL3016/DL3062 fire. Under the pinning doctrine (epic #155) floating is the default and version management lives in docker/pins/, so these rules fight policy — ignore them, matching the existing DL3008/DL3028 precedent. CI hadolint now clean.

- **add pin exposure report: due-for-re-evaluation + installed versions per image (#430)**
Reports pins whose inducing_release is no longer leading edge, plus resolved installed versions per image (pinned AND floating), and links the §4.3 lifecycle. Harvest probe is injected so unit tests stay hermetic; internal-state only, upstream drift is the Dependabot follow-on (#158).
