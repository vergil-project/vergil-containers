
# Release 2.1.17 (2026-08-05)

## Bug fixes

- **close C++ image gaps found by T11 (Conan profile, run-clang-tidy, llvm-cov gcov, osv-scanner) (#488)**
T11 cold-rebuild validation (#2558) surfaced four deployment gaps in the published C++ images. Fix them in the image definitions so the vergil-tooling C++ command registry works cold:

- Bake a default Conan profile: each cpp-clang/cpp-gcc image runs 'conan profile detect' at build time into a fixed CONAN_HOME (/opt/conan2), so 'conan install' resolves cold under any HOME (local /root vs CI /github/home) without the caller running profile detect. build_type is left at Conan's default; the registry INSTALL command passes -s build_type explicitly (#2572).
- Expose an unversioned run-clang-tidy on PATH via update-alternatives in the shared analysis fragment, so LINT no longer exits 127 (only run-clang-tidy-20 existed before).
- Clang images ship a gcov shim that dispatches to 'llvm-cov gcov', so the compiler-agnostic gcovr/coverage command works in the Clang family with no compiler dimension in the registry. GCC images keep their native gcov, untouched.
- Install osv-scanner (the new AUDIT tool replacing conan audit, #209) from its prebuilt GitHub release binary in the shared analysis fragment, verified against osv-scanner_SHA256SUMS. It is an exact-version pin, registered as an auto-managed entry in docker/pins (pins.yml, resolve_latest.py, CATALOG.md) and bumped weekly like nfpm/trivy.

The smoke fixture now runs 'conan install' cold (no profile detect) and asserts run-clang-tidy resolves, osv-scanner runs, and the Clang gcov dispatches to llvm-cov. All four images (cpp-clang 20/19, cpp-gcc 14/13) build and smoke-pass on nerdctl. Requires a vergil-containers re-release to rebuild and republish the images.
