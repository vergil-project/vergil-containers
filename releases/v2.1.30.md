
# Release 2.1.30 (2026-10-22)

## Bug fixes

- **run the lifecycle tests on a frozen manifest, not the live one (#658)**
The lifecycle and generator tests read docker/versions/manifest.yml and asserted today's version lists, so every add or drop PR the lifecycle automation opened failed its own CI (#650, #651). They now read docker/versions/testdata/manifest.yml, a frozen snapshot, and a repo tree regenerated from it (frozen.py). The only test on the live manifest, test_real_manifest_is_valid, checks it loads, is canonical and that the generated files are up to date; it asserts no version list.


## Chores

- **re-audit .trivyignore against fresh scans of the current image matrix (#634)**
Built all 14 publish images locally on arm64 from scratch (the 13 matrix.json entries plus dev-base) and scanned each with Trivy 0.72.0 without .trivyignore or the rego, keeping only ignore-unfixed and skip-files. All 33 entries appear in at least one fresh scan, so none is removed, and no carrier has a newer upstream release to bump to.

Updated the Last audited header.

With the full trivy.yaml, .trivyignore and rego, all 14 images report 0 HIGH/CRITICAL.


## Features

- **add the report-only language adapters (#633)**
Add lifecycle adapters for Rust, Java, Node (ts-node), Clang and GCC, each implementing the support rule on its docs/site/docs/languages policy page, so every manifest family now has an adapter. Generic source helpers (url_exists, index_links, github_releases, debian_source_in_suite) go in sources.py; the gcc.gnu.org page parsing lives in the GCC adapter because it is language-specific. Tests use recorded 2026-10-21 fixtures and never touch the network.

- **run the language lifecycle check nightly with issues for gaps and failures (#635)**
- **open add and drop PRs for Python and Go (#636)**
The nightly language-lifecycle job now opens one App-authored PR per add or drop on a pr-automation family (lifecycle/<family>-<kind>-<version>), carrying the manifest edit and every regenerated file. A rerun rebuilds the branch deterministically, force-pushes only when it changed, and refreshes the same PR; a PR whose change is no longer reported is closed. Nothing auto-merges, and add PRs carry a hold until the first-adds validation task (#622) closes. Blocked and EOL-soon versions on pr families now get issues. Ref #618

- **record the published vergil-python runtime from the apt index (#638)**
The lifecycle check now reads the signed vergil apt index and records, for each Python version, whether its vergil-python<x.y> runtime package is published. A version recorded without a runtime that now has one gets a runtime PR setting runtime_published: true; a recorded runtime that disappears opens a runtime_missing issue. A package listed for only some suites or architectures, and any index fetch or parse failure, fails the family loudly. Ref #621
