
# Release 2.1.32 (2026-10-25)

## Bug fixes

- **fill in the upstream ga/eol dates for the seeded manifest versions (#674)**
Every seeded version now carries the GA and EOL dates its lifecycle adapter would record, taken from upstream (python.org release-cycle data and PEPs 693/719/745, Adoptium, the Node.js release schedule, go.dev, Rust RELEASES.md, the llvm-project GitHub releases, gcc.gnu.org). EOL stays null where upstream publishes no date (Go, Rust, LLVM, GCC); the manifest header now says so, since per-entry comments would not survive dump_manifest. Regenerated window.json. Ref #673

- **bump the smoke fixture to vitest 5 to clear its npm lockfile advisories (#676)**
Bump vitest and @vitest/coverage-v8 from ^3.2.0 to ^5.0.5 and regenerate package-lock.json inside dev-ts-node:24. This drops tinypool and brace-expansion from the tree and moves vite to 8.3.5, source-map-js to 1.2.2 and vitest/@vitest/mocker to 5.0.5, clearing all 13 OSV/Dependabot advisories (npm audit: 0 vulnerabilities). vitest 5 matches the floating global vitest the ts-node images ship (5.0.5), so the smoke test exercises the same major as the image. Ref #675

- **ignore CVE-2026-109869 in npm's bundled undici until npm ships a fix (#679)**
npm 12.2.1 (the latest release) and 11.21.1 both still bundle undici 6.29.0, so no npm bump clears CVE-2026-109869, which gates every image in the nightly publish. Inside npm's tree only node-gyp's header download uses undici fetch(); npm's registry traffic does not. Triggering the crash needs a malicious TLS-authenticated header server, and the impact is a crash of a short-lived install. Add a carrier block whose removal condition is an npm release that bundles undici >= 6.29.1, which the ^12.2.1 range picks up on rebuild. Ref #677.

## Features

- **add rpm to every dev image, as the peer of dpkg (#694)**
Install the distro's rpm via a new common/rpm.dockerfile fragment, wired into the base and every language template after nfpm. Package tests need rpm.vercmp to verify .rpm version ordering for real instead of skipping.

The fragment asserts at build time that rpm --version runs and that rpm.vercmp(1.0, 1.1) prints -1, so every published image on both platforms is proven to carry a working rpm with its embedded Lua. Unpinned apt install, like pandoc.
