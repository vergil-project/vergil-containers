
# Release 2.1.25 (2026-08-13)

## Bug fixes

- **build nightly prod images from main, not develop (#544)**
Add an optional `ref` input to cd-docker-publish.yml (empty default = the caller's triggering ref, so the push path via cd.yml is unchanged) and consume it in all three checkout steps (hadolint, build-scan-push, publish-base).

In ops.yml, pin the scheduled rebuilds explicitly: dev builds from develop, prod builds from main. Previously both nightly jobs inherited the schedule's default branch (develop), so prod-* images were built from unreleased develop source, collapsing the dev-leads/prod-trails canary.

- **triage CVE-2026-46600 (x/net in bundled Go CLIs) to unblock CD publish (#549)**
The Trivy CRITICAL/HIGH gate in cd-docker-publish.yml has failed on every dev image since #544 on a single new CVE: CVE-2026-46600 (HIGH, golang.org/x/net, fixed in v0.56.0) — an SVCB/HTTPS DNS resource-record parse can panic (DoS) in x/net/dns/dnsmessage.

x/net is vendored inside several third-party prebuilt Go CLIs in the common layer (three affected versions observed: v0.50.0/v0.54.0/v0.55.0), so no bump we can make reaches x/net >= 0.56.0 today. The affected tools are build-time lint/scan/CLI utilities that never parse attacker-controlled DNS responses, so the vulnerable path is not exercised. Suppress with a documented justification per the .trivyignore convention; remove once the bundled tools vendor x/net >= 0.56.0.
