
# Release 2.1.12 (2026-07-28)

## Bug fixes

- **drop secrets: inherit from cd.yml (no publish, needs no secrets) (#448)**
The cd-release release job passes no language so no package-publish step runs and no secret is used; the docker-publish job uses GITHUB_TOKEN via packages: write, not an inherited secret. Remove blanket secrets: inherit (least-privilege). Ref vergil-project/.github#189.

- **package-cleanup startup_failure — newline inside ${{ }} (#449) (#450)**
The dry-run arming expression in both jobs was written as a >- folded scalar whose continuation lines were indented deeper than the opening ${{ line. YAML preserves newlines on more-indented lines in a folded scalar, so the value carried embedded newlines inside the ${{ }} expression. GitHub rejects a newline inside an expression at parse time, which is why every scheduled run since the workflow landed (06-30) has been a 0s startup_failure with no job logs — so neither cleanup nor the reap-aliases datestamp reaper (#426) has ever run. actionlint tokenizes expressions loosely and did not catch it.

Dedent each continuation line to match the ${{ line so the fold collapses the newlines to spaces, yielding a single-line expression with byte-identical arming semantics. Add a guard comment in both jobs so a future re-indent cannot silently reintroduce the failure.

- **allow dataaxiom/ghcr-cleanup-action via [actions] override (#452)**
The package-cleanup workflow errors at startup because dataaxiom/ghcr-cleanup-action is outside the org base allowed-actions policy. Declares the per-repo [actions].extra-allowed-patterns override (vergil-tooling#2524) so vrg-github-repo-config apply unions the specific action into this repo's live selected-actions policy. Least-privilege: the named action at any version, not dataaxiom/*. Completes the allowlist half that #449 was meant to cover before it was superseded by the unrelated newline change in #450. Ref #451.

- **drop reap-aliases exclude-tags rejected by the ReDoS guard (#454)**
The reap-aliases job errored on all 12 packages because dataaxiom/ghcr-cleanup-action rejects the exclude-tags regex as ReDoS-prone (nested quantifier in the version alternative). Drops exclude-tags entirely: the delete rule already selects only datestamp aliases, and across all 12 packages no rolling/version/cache/candidate tag ends in -YYYYMMDD, so the net was redundant. Removing it eliminates the ReDoS surface; DRY-RUN-by-default arming and the #436 dry-run preview still gate any real deletion. Ref #453.

## Features

- **auto-manage 9 binary tools via weekly leading-edge bumper (#443)**
* feat(pins): auto-manage 9 binary tools via weekly leading-edge bumper

Introduce Approach B (periodic auto-bump, pinned-in-source) for the 9 binary-download mechanism tools (shellcheck, shfmt, actionlint, git-cliff, hadolint, opentofu, nfpm, trivy, scorecard) per #435.

- Add docker/pins/resolve_latest.py: per-tool leading-edge resolver via the /releases/latest redirect (curl -fsSLI, parse location header) — not api.github.com. Normalizes the v prefix to the bare ARG convention, fails loud on any resolution failure, and rewrites the ARG *_VERSION pins in the fragments. Hermetic unit tests inject the fetch (no network).
- Add .github/workflows/bump-tools.yml: weekly cron + workflow_dispatch that runs the resolver, rewrites the pins, regenerates CATALOG.md, and opens a reviewed bump PR on drift (GITHUB_TOKEN, no auto-merge). No-op otherwise.
- Add auto-managed pin state: convert the 9 tools to auto-managed with a descriptive constraint (never a hard-coded version, so pins.yml cannot drift from the template). check_pins now validates states and accepts auto-managed; report_exposure surfaces auto-managed as its own category.

Normal builds and generate.sh stay hermetic/offline — only the scheduled bumper touches the network.

- **add pandoc to base + language images (#457)**
Install pandoc via apt (--no-install-recommends, no texlive) in a new common/pandoc.dockerfile fragment, wired into base and all five language templates. Enables managed markdown -> .docx conversion via vrg-container-run -- pandoc; the driver is research-report publishing to Google Docs (a .docx imports as a native Doc).

Unpinned by design: apt pandoc floats cleanly, so it stays out of the docker/pins/ mechanism-pin set per the repo pinning doctrine. Docs inventory and CLAUDE.md common-layer list updated.
