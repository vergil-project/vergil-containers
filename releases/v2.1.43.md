
# Release 2.1.43 (2026-11-16)

## Bug fixes

- **run reap-aliases after cleanup so the two never race on a package (#911)**
reap-aliases now needs cleanup, with if: !cancelled() so a failed cleanup leg does not skip the reap. Overlapping legs made reap-aliases load manifests that cleanup was deleting, and fail with HTTP 404. The back-off warning and the persistent-failure error now name the 404 case as a deletion race rather than a rate limit. Tests pin the ordering and the 404 wording; the package-hygiene doc describes the ordering.

- **run the images' auto-managed Trivy in the CI and publish gates (#915)**
* fix(ci): run the images' auto-managed Trivy in the CI and publish gates

The CI and publish Trivy gates pinned aquasec/trivy:0.72.0 in the workflows, where neither the upstream refresh nor Dependabot moves it. Each gate now reads the image from the auto-managed ARG TRIVY_VERSION in docker/common/security-tools.dockerfile (docker/pins/workflow_images.py trivy-image), so it runs the Trivy the images ship. workflow_images.py check, run by validate-custom, fails on any image a workflow pins by a literal version unless it is declared as accepted. Ref #855.

* fixup! fix(ci): run the images' auto-managed Trivy in the CI and publish gates

- **resolve every pinned tool in the pin-exposure report (#916)**
The report kept its own copy of the tool-to-repo map, which lacked yq and cargo-nextest, so their upstream showed as unknown. Build the map from resolve_latest.TOOL_REPOS plus a report-only entry for go-test-coverage, resolve each tool through a shared resolve_latest.resolve_tool (so cargo-nextest goes to get.nexte.st with its tag prefix), warn on a pinned tool with no repo, and test that every pins.yml tool has an entry. Drops the dead golangci-lint, cargo-deny and cargo-llvm-cov entries, which are no longer pinned. Ref #901


## CI

- **move the image build's registry service to 3.x under a managed pin (#919)**
* ci(pins): move the image build's registry service to 3.x under a managed pin

PR CI's job-local registry service ran registry:2.8.3, a literal pin no update mechanism moved. Move it to registry 3.1.2 (its default configuration serves the job's plain-HTTP, no-auth localhost:5000 use unchanged) and pin it in docker/pins/workflow-images.txt, which the upstream refresh moves to the newest distribution/distribution release within the pinned major version only: a new major fails the refresh with an error before anything is written. ci-images.yml derives the service image through workflow_images.py registry-image, as it derives Trivy's, the UNMANAGED entry is gone, and a change to the pin rebuilds every image in PR CI. Ref vergil-project/vergil-containers#914

* fixup! ci(pins): move the image build's registry service to 3.x under a managed pin

## Features

- **make live deletion the default and retire the dry-run gate (#912)**
The scheduled run now always deletes for real; the PACKAGE_CLEANUP_DRY_RUN repository variable no longer gates it, so git alone records what the cleanup does. A manual run keeps the dry_run input for previews, now defaulting to false, so it deletes unless the caller asks for a preview. The dry-run expression is one line with no fall-through branch. The workflow comments and the package-hygiene doc describe the live job and the preview option; tests pin the input default, the expression and the absence of any repository variable.

- **pin prebuilt tool digests in source and verify cargo-nextest against them (#920)**
The daily refresh now resolves each TOOL_DIGESTS tool's per-architecture sha256 from its release checksum files at the version it writes, and writes versions and digests together, all or nothing. The cargo-nextest fragment pins CARGO_NEXTEST_SHA256_AMD64 and _ARM64 (seeded from the 0.9.152 release) and verifies the tarball against them instead of a downloaded .sha256. Ref vergil-project/vergil-containers#917.

- **pin cargo-deny and cargo-llvm-cov through refreshed fragments (#922)**
cargo-deny moves to docker/common/cargo-deny.dockerfile: the release's musl tarball, verified against per-architecture SHA-256 digests pinned in source and written by the refresh (TOOL_DIGESTS). cargo-llvm-cov moves to docker/common/cargo-llvm-cov.dockerfile: cargo install --locked at a pinned CARGO_LLVM_COV_VERSION. Both are registered with the daily upstream refresh and are auto-managed pins; pins.yml records the reversal of the WS2 (#418) free. Seeded at cargo-deny 0.21.0 and cargo-llvm-cov 0.9.1.

Ref vergil-project/vergil-containers#918
