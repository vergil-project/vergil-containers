
# Release 2.1.16 (2026-08-04)

## Bug fixes

- **stop Trivy flagging pip-vendored CVEs via pip's bundled SBOM (#483)**
The v2.1.15 docker-publish gate failed on base + python with setuptools 70.3.0 (CVE-2025-47273). Root cause: pip 26.x ships pip/_vendor/bom.cdx.json, a CycloneDX SBOM of pip's vendored dependencies, and Trivy 0.72.0 ingests it and reports those vendored packages (setuptools 70.3.0, msgpack 1.1.2) as image CVEs with a null package path. They are pip internals, not the image's runtime attack surface. The #474 setuptools bump upgraded the real system setuptools (kept here) but could not touch pip's vendored copy.

Verified on the actual prod-base candidate: removing pip/_vendor/bom.cdx.json clears both the setuptools and msgpack findings; leaving it reports both.

- base + python templates: after the pip upgrade, delete pip/_vendor/bom.cdx.json. Clears the whole pip-vendored-SBOM false-positive class at the source instead of accreting a suppression per vendored dep.
- .trivyignore: drop the now-superseded msgpack suppression (GHSA-6v7p-g79w-8964); the SBOM removal clears it. brace-expansion / ip-address (npm-bundled) stay suppressed.


## CI

- **publish C++ images to GHCR (#482)**
Wire the four C++ images into the GHCR publish pipeline so prod-cpp-* / dev-cpp-* are actually published. The merged T1/T2 (#467/#468) registered them only for the local builder (docker/build.sh, docker/generate.sh); the publish matrix had no C++ entries, so every C++ tag returned 403 on GHCR.

- cd-docker-publish.yml: add cpp-clang {20,19} (CLANG_VERSION) and cpp-gcc {14,13} (GCC_VERSION) to the build-scan-push matrix, mirroring the local builder's language/build-arg/version mapping and image names (prod-/dev-cpp-clang, prod-/dev-cpp-gcc).
- report_exposure.py: add cpp-clang and cpp-gcc to _MATRIX so installed tool versions are harvested for the C++ images; add a covering test.
- CLAUDE.md: add C++ (Clang/GCC) to the Version Matrix and the per-package GHCR write-access setup list.
