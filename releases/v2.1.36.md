- **retry the per-arch push by digest on a sporadic GHCR denial (#796)**
GHCR sporadically refuses one per-arch push with write_package while the same token pushes the same package around it. Run the push as up to three attempts with a bounded, jittered back-off (15-45s, workflow env PUSH_RETRY_BACKOFF_*) that warns before each retry, fail loudly naming image and arch after the third, and record the digest of the attempt that succeeded. Applies to every tier through the shared build steps. Ref #794

- **build and scan only the images a PR changes, with one aggregating gate (#795)**
* feat(versions): group PR CI's selected images into per-tree build jobs

A selected parent and its selected descendants share one job per architecture, parents first, since PR CI never pushes an image; a child selected alone builds on its published dev- parent. Each entry carries its smoke-test directory. Ref vergil-project/vergil-containers#514.

* ci(images): build and scan only the images a PR changes, with one aggregating gate

ci.yml calls the new ci-images.yml on pull requests: images / select runs selection.py and pr_jobs.py on the PR's diff and base matrix, images / build builds each job natively per arch with a read-only cache, scans and gates it with the publish scripts and runs its smoke test (scripts/bin/pr-image-build), pushing nothing to GHCR, and images / evidence is the one required check. Ref vergil-project/vergil-containers#514.

* fix(images): run the select step under bash and its scripts with uv run

PR CI's select job runs in the prod-base container, where a step with no shell gets sh -e, so the SHA check's [[ =~ ]] failed every PR. Default every run step in ci-images.yml to bash, and test it. Run selection.py and pr_jobs.py with uv run, as #777 requires of every entry point, and give pr_jobs.py its PEP 723 block. Ref #514.


## Features

- **build images in tiers from their manifest parents, with per-entry build args (#775)**
* feat(versions): build images in tiers from their manifest parents, with per-entry build args

A family or base may name a manifest parent; load_manifest refuses a missing parent, a cycle or a depth over 2. Each matrix.json entry now carries a build-args map, its parent and its depth, ordered by depth. cd-docker-publish.yml builds and publishes one tier per depth, each child FROM its parent's promoted digest from the same run, and docker/build.sh builds from matrix.json in the same order, a named family after its parents. No entry names a parent yet, so everything stays in tier 0. Ref vergil-project/vergil-containers#773

* docs(versions): point the family READMEs at the manifest, not build.sh's removed build lines

- **derive each image's @include dependency graph (#784)**
- **select the images a change affects from its paths and matrix diff (#791)**
Add docker/versions/selection.py for PR CI (epic vergil-project/.github#213, T5): the union of the full set (pipeline and scan-config paths), the matrix.json diff and the @include dependency graph, closed over descendants so a selected parent rebuilds its children. No-build paths select nothing; an unclassified path under docker/ fails closed to the full set with a ::warning::. Ref vergil-project/vergil-containers#513

- **add a toolchains section for non-language images (#793)**
manifest.py parses, validates and round-trips an optional toolchains: section (key, build_arg, versions newest first) whose keys share the family namespace, so any entry may name a toolchain as its parent. generate.py emits toolchain entries into matrix.json, the build.sh smoke table, the package cleanup and cache-warm lists, the template ARG defaults and the docs tables, never window.json. includes.dependency_map covers toolchain keys so the PR selector does not fail their paths closed, and lifecycle apply_change keeps every manifest section it does not change.

Ref vergil-project/vergil-containers#727

- **add pkg-ubuntu and pkg-rhel package toolchain images (#797)**
* feat(images): add pkg-ubuntu and pkg-rhel package toolchain images

Add the pkg-ubuntu (26.04, 24.04) and pkg-rhel (10, 9) package toolchain images under the manifest's toolchains section (epic vergil-project/.github#607, Task 4). Each is the upstream image plus the OS upgrade, the package-toolchain prerequisites, a pinned checksum-verified uv (new common/uv.dockerfile, auto-managed), nFPM, the toolchain marker and, on amd64 pkg-ubuntu, the apt mirror and fail-fast config os-prereqs.sh writes. Build-time checks fail the build on a wrong mirror config per architecture, a missing tool, a short marker, an added python or kept package lists. Neither template sets ENTRYPOINT, CMD, USER or WORKDIR (test_pkg_templates_set_no_inherited_config). The pins exposure report now covers every toolchain image, and the upstream refresh floats UV_VERSION.

Ref vergil-project/vergil-containers#728

* fix(images): write the apt fail-fast config on every arch in pkg-ubuntu

os-prereqs.sh writes 80-vergil-fast-fail on every architecture and limits only the mirror list and sources rewrite to amd64. The fragment now does the same, and the pkg-ubuntu build-time check requires the fast-fail file on amd64 and arm64 alike. Per the merge-review ruling on R1 (ref #728).

* fix(images): build the toolchain images in PR CI and clear their hadolint warnings

PR CI's job planner (pr_jobs.smoke_dirs) listed manifest families only, so a PR selecting pkg-ubuntu or pkg-rhel failed with no manifest entry. It now covers every toolchain entry. SC3054 on the marker step and DL3006 on the UBI FROM are ignored inline with their reasons: the step runs under the template's bash SHELL, and the RHEL version is in the repository name.
