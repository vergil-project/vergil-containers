
# Release 2.1.39 (2026-11-12)

## Bug fixes

- **choose the mirror list from the archive hosts ubuntu.sources names (#846)**
Ubuntu 26.04 serves arm64 from the main archive, so its ubuntu.sources names archive.ubuntu.com and security.ubuntu.com on arm64, where 24.04 names ports.ubuntu.com. The fragment chose the rewrite from TARGETARCH, rewrote nothing on 26.04 arm64, and the build-time check failed. The fragment now reads the Ubuntu URIs the sources name: the ubuntu archive hosts get the main-archive list (amd64's list, unchanged, whose hosts all serve resolute arm64), ports.ubuntu.com gets the ports list on arm64, and any other ubuntu.com host, a mix of both archives, or neither fails the build. The build-time check follows the same rule, asserts every URIs line is the mirror list and no active apt source names ubuntu.com, and names the assertion that failed. Ref vergil-project/vergil-containers#844

- **re-run the pkg images' OS upgrade on the first build of each UTC day (#847)**
* fix(pkg): pass the run's UTC date as UPGRADE_DATE to images that declare it

cd-docker-publish.yml's versions job and ci-images.yml's select job compute the UTC date once per run and every build of an image whose Dockerfile declares a bare ARG UPGRADE_DATE gets it; docker/build.sh computes it once per run too (VRG_UPGRADE_DATE overrides it locally). A missing or malformed date, or an ungenerated Dockerfile, fails loudly. Ref vergil-project/vergil-containers#845

* fix(pkg): re-run the pkg images' OS upgrade on each new UTC date

pkg-ubuntu's apt-get upgrade and pkg-rhel's dnf upgrade now follow a bare ARG UPGRADE_DATE and check it first, so the date is part of the upgrade layer's cache key: the first build of each UTC day re-runs the upgrade instead of reusing a cached one until the base image digest changes. A build with no date, or a malformed one, fails. Ref vergil-project/vergil-containers#845

* docs(pkg): describe the daily UPGRADE_DATE of the pkg images' OS upgrade

Ref vergil-project/vergil-containers#845
